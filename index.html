If replay is triggered after cut-off, the booking succeeds but settlement silently fails downstream. The system must flag REQUIRES_AMENDMENT and notify the front office — not auto-replay.
Idempotency controls
Checking downstream_state alone is insufficient to prove replay safety. The table is written by the same process that is failing — it may itself be stale or inconsistent.
UNIQUE (trade_ref, workflow_stage)
ON CONFLICT → upsert, not insert
Constraint violation = duplicate detected
The database enforces idempotency — not application-level state checks alone. If a replay attempts to re-book a trade that was already committed (ACK lost), the unique constraint rejects it with a constraint violation, not a silent success.
Poison message & quarantine
A poison message fails on every attempt regardless of infrastructure state — malformed data, missing reference data, business rule violation. Without a max-retry limit, the engine loops indefinitely.

1–2Auto-retry with backoff
